VARIANT and Semi-structured Data study card for SnowPro Core

The essentials

VARIANT limits

  • Max size: 16 MB compressed (~128 MB uncompressed)
  • Stores JSON, Avro, ORC, Parquet
  • Auto-extracts up to 200 elements per partition into columnar form

VARIANT vs flatten — when to flatten

  • Dates/timestamps (esp. non-ISO 8601)
  • Numbers stored as strings
  • Arrays
  • Unknown schema? → keep as VARIANT for now
Subcolumnarization — how Snowflake auto-optimizes VARIANT
Snowflake tries to extract VARIANT elements into hidden columnar form for faster scans. Two cases where it won't extract:

❌ Not extracted if…

  • Element contains even one JSON null value
  • Element has mixed data types across rows
    e.g. foo=1 in row 1, foo="1" in row 2

✅ Fix it by…

  • Flatten nulls to relational columns before loading
  • Use STRIP_NULL_VALUES=TRUE in file format
  • Ensure consistent data types per element
Two types of NULL — biggest exam trap
SQL NULL

Value is missing or unknown. Standard SQL behaviour. Stored as true NULL.

PARSE_JSON(NULL) → NULL

JSON null (VARIANT NULL)

Stored as the string "null" inside VARIANT. Looks like null but is not SQL NULL.

PARSE_JSON('null') → null

Convert JSON null → SQL NULL: cast with TO_VARCHAR() or TO_CHAR().
In an ARRAY: SQL NULL = undefined · JSON null = null
Exam traps
Trap 1 — size limit
VARIANT max is 16 MB compressed / ~128 MB uncompressed. Not unlimited.
Trap 2 — null blocks extraction
Even ONE JSON null in an element prevents that element from being columnarized → slower queries.
Trap 3 — mixed types block extraction
Same key storing a number in one row and a string in another = not extracted. Keep types consistent.
Trap 4 — SQL NULL ≠ JSON null
They look similar but behave differently. JSON null is a string. SQL NULL is absence of value.
Trap 5 — extraction limit
Snowflake extracts max 200 elements per partition. Beyond that, elements stay in raw semi-structured form.
Practice questions
Score:0 / 0
1. Which scenario should trigger flattening VARIANT data into relational columns?
Flatten when you have dates/timestamps (especially non-ISO 8601), numbers in strings, or arrays — these perform poorly in VARIANT. Native strings and integers are fine in VARIANT.
2. Why would Snowflake NOT extract a VARIANT element into columnar form?
Even one JSON null value in an element blocks columnar extraction for that element. Also blocks: mixed data types across rows. Fix: use STRIP_NULL_VALUES=TRUE or flatten before loading.
3. What is the result of PARSE_JSON('null') in Snowflake?
PARSE_JSON('null') returns a VARIANT null (JSON null) — a string "null", not SQL NULL. PARSE_JSON(NULL) — passing SQL NULL — returns SQL NULL. They look similar but are fundamentally different.
4. What is the maximum number of VARIANT elements Snowflake extracts into columnar form per partition by default?
200 elements per partition per table is the default extraction limit. Beyond 200, elements stay in raw semi-structured form and require full JSON traversal to query — slower. Contact Snowflake Support to increase this.
