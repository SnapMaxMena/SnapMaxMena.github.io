Multi-factor authentication (MFA)
SnowPro Core — quick-review card
MFA applies to — user type matters
👤 Human users
Authenticate with password.
MFA required (or becoming required).
Must enroll in MFA.
🤖 Service users
Programmatic access.
MFA NOT required.
Must use other auth methods (key pair, OAuth, etc.)
⚠ Snowflake is rolling out mandatory MFA for all password sign-ins. Opt-out is temporary. Accounts created after 2024_08 bundle: MFA required by default.
MFA methods — 4 types
🔑 Passkey
Recommended. Stored in device/hardware. Most secure + usable. Can be replicated.
📱 TOTP
Authenticator app (e.g. Google Authenticator). Time-based one-time passcode. Can be replicated.
📲 Duo
Push notification or Duo passcode. NOT replicated like other methods. Default for CLI/SnowSQL/JDBC/ODBC/Python.
🔢 OTP (One-time passcode)
Generated for break glass access only. Single-use — invalidated after use. NOT replicated across accounts. Generate with ALTER USER … ADD MFA METHOD OTP COUNT = N
Restrict methods via authentication policy: MFA_POLICY = (ALLOWED_METHODS = ('PASSKEY', 'TOTP'))

MFA token caching — reduce prompts
What it does
Caches the MFA token so users aren't re-prompted for multiple connections within a short period. Valid up to 4 hours.
Enable
ALTER ACCOUNT SET ALLOW_CLIENT_MFA_CACHING = TRUE
Authenticator string: username_password_mfa
Role: ACCOUNTADMIN
Token invalidated when any of these occur:
ALLOW_CLIENT_MFA_CACHING set to FALSE
Authentication method changes
Username or password changes
Credentials invalid
Token expires or fails cryptographic check
Account name changes
Token stored in client OS keystore. Consult security/compliance team before enabling.
Lockout recovery — 2 admin options
Option A — Add new MFA method
ALTER USER joe ENROLL MFA;
If verified email → Snowflake emails a link.
If no email → Snowflake returns a URL the admin sends to user.
Option B — Temp bypass
ALTER USER joe SET MINS_TO_BYPASS_MFA = 30;
Grants single-factor login for N minutes. Admin resets afterward.
Break glass access — emergency admin login
Create a dedicated break-glass user. Store password + OTPs in a key vault.
OTP is single-use — invalidated immediately after authentication.
OTPs cannot be replicated across accounts. For target accounts: generate new OTPs there, or use TOTP/passkey instead.
Always have a backup MFA method — if OTPs are exhausted and no other method exists, user is locked out.
MFA connector support at a glance
Fully supported
Snowsight · SnowSQL · Snowflake CLI · JDBC · ODBC · Python · Node.js · .NET
Default behavior
Duo Push used by default in SnowSQL, CLI, JDBC, ODBC, Python. No config change needed.
Passcode instead of Push
--mfa-passcode <code> or passcodeInPassword=true (appends code to password string)
⚠ MFA with landline/phone callbacks does NOT work with drivers (ODBC, JDBC, etc.).
