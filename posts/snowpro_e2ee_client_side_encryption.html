Snowflake decrypts data during processing/transformation in a table, then re-encrypts when operations complete. Data is never stored unencrypted at rest.
Internal vs external stage — encryption behavior
🏠 Internal stage (Snowflake-provided)
Auto-encrypted by Snowflake client on user's local machine before transmission.
Also encrypted again after loading into the stage.
No customer action required — fully automatic.
Files unloaded to internal stage are automatically encrypted.
☁️ External stage (customer-provided)
Client-side encryption is optional but recommended.
If NOT encrypted before upload → Snowflake encrypts immediately on load into table.
Files unloaded to external stage are optionally encrypted using client-side encryption.
Examples: Amazon S3, GCS, Azure Storage
Client-side encryption protocol — upload flow
1
Customer creates a secret master key (128-bit or 256-bit AES, Base64-encoded). This is shared with Snowflake.
2
The cloud storage client generates a random file encryption key → encrypts the file with this random key → then encrypts the random key itself with the customer's master key.
3
Both the encrypted file and the encrypted random key are uploaded to cloud storage. The encrypted random key is stored in the file's metadata.
↓
Download reversal: Client downloads both → decrypts random key using master key → decrypts file using random key. All decryption happens on client side.
⚠ At no time does the cloud storage service, ISP, or any third party see the data in plaintext.
MASTER_KEY — how to configure client-side encryption
Create encrypted external stage
CREATE STAGE encrypted_stage
URL='s3://bucket/data/'
CREDENTIALS=(
AWS_KEY_ID='...'
AWS_SECRET_KEY='...'
)
ENCRYPTION=(MASTER_KEY='eSxX...=');
Load from encrypted stage
COPY INTO users
FROM @encrypted_stage/users;
Unload to encrypted stage
COPY INTO @encrypted_stage/out
FROM my_table;
MASTER_KEY requirements
128-bit or 256-bit AES key
Encoded in Base64
Transmitted to Snowflake via HTTPS/TLS
Stored encrypted in metadata storage
Named stages can be granted to other users without revealing the master key or credentials — access-controlled reference only.
