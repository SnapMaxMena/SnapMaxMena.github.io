Snowflake Key Concepts Study Guide for SnowPro Core Certification

Core pattern: Snowflake = hybrid of shared-disk (central storage accessible by all) + shared-nothing (MPP clusters where each node stores data locally). Best of both worlds.
Storage

Database storage

  • Columnar, compressed, internally optimized
  • Auto-divided into micro-partitions
  • Managed entirely by Snowflake
  • Supports structured, semi-structured & unstructured
  • Stored on cloud provider (AWS/Azure/GCP)
Compute

Virtual warehouses

  • Cluster of compute resources
  • Processes SQL + Snowpark code
  • Each is independent — no resource sharing
  • Runs Java, Python, Scala via Snowpark
  • Supports Apache Spark™ workloads
Cloud Services

Cloud services layer — ties everything together

🔐 Security & auth
📋 Horizon Catalog
🏗 Infra management
🗄 Metadata mgmt
⚡ Query optimization
📜 Compliance
Snowflake is a SaaS (self-managed service). No hardware to install or manage. Cannot run on-premises or on private cloud. Snowflake handles all maintenance, upgrades, and tuning.
Three table types, each for a different purpose. Know when to use each — this is a common exam area.
Snowflake tables

Best for: data warehouses

Columnar + compressed. Internally managed by Snowflake. Auto micro-partitioned. Stores structured & semi-structured data. FILE type for unstructured.

Apache Iceberg™ tables

Best for: existing data lakes / lakehouses

External storage (S3, Azure, GCS) that you manage. Same query performance as Snowflake tables. Data stays outside Snowflake. Structured & semi-structured.

Hybrid tables

Best for: Unistore (OLTP + OLAP together)

Row locking. Index-based reads/writes. Enforces unique + referential integrity constraints. Low latency + high throughput. Transactional workloads.

Key definitions

Virtual warehouse — cluster of compute resources. Processes SQL/Snowpark. Each is independent (no resource sharing between warehouses).
Micro-partition — contiguous unit of storage. All Snowflake table data is auto-divided. Enables efficient pruning and compression.
Snowgrid — cross-region, cross-cloud layer. Enables listings, consistent governance, and replication across AWS/Azure/GCP.
Snowpipe vs Snowpipe Streaming — Snowpipe ingests files as they arrive in a stage. Snowpipe Streaming ingests rows continuously via SDK/REST with lower latency.
Cloud services — coordinates all activities: auth, query parsing+optimization, metadata, governance, infra mgmt. Runs on Snowflake-provisioned compute.

1. Snowflake's architecture is best described as a hybrid of which two approaches?
Central data repository = shared-disk simplicity. MPP clusters where each node stores data locally = shared-nothing performance. The hybrid gives you both data management simplicity and scale-out benefits.
2. Which table type should you choose for transactional workloads that require row locking and referential integrity?
Hybrid tables are optimized for low-latency, high-throughput OLTP with row locking and unique/referential constraints. They power the Unistore workload pattern (OLTP + OLAP in one platform).
3. A data engineer needs to ingest row-level data continuously with low latency directly into Snowflake tables via an API — without staging files. Which feature should they use?
Snowpipe Streaming loads row-level data continuously via Snowflake SDKs or REST API — no files, no staging. Regular Snowpipe still requires files in a stage. COPY INTO is a batch command.
4. Which layer of Snowflake's architecture is responsible for query parsing and optimization?
The cloud services layer handles query parsing and optimization, along with authentication, metadata, governance, and infrastructure management. Virtual warehouses execute queries but don't optimize them.
5. What is TRUE about virtual warehouses?
Each virtual warehouse is fully independent — no shared compute with other warehouses. This means one busy warehouse has zero performance impact on others. Storage is managed separately by the storage layer, not the warehouse.
6. An organization has an existing data lakehouse on Amazon S3 and wants Snowflake query capabilities without moving data. Which table type fits?
Iceberg tables combine Snowflake query semantics with external cloud storage you manage. Data stays in S3 (or Azure/GCS) — ideal for existing data lakes/lakehouses you can't or won't migrate to Snowflake.
7. Snowgrid enables which of the following capabilities?
Snowgrid is Snowflake's cross-region, cross-cloud technology. It enables cross-cloud listings/collaboration, consistent security/governance policies across providers, and disaster recovery via replication. Containerized apps are handled by Snowpark Container Services.
