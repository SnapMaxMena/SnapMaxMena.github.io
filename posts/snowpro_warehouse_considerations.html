Warehouse cache — the hidden gotcha
Each running WH maintains a local data cache. Larger WH = bigger cache.
Cache is dropped on suspend. First queries after resume will be slower until cache rebuilds.
Trade-off: suspend to save credits vs keep running to preserve cache.
Downsizing a running WH also drops the cache for removed compute resources — same performance hit as suspend.

SettingRecommendationWhen to change
Auto-suspend valueSet low (5–10 min or less)If queries arrive every 2–3 min → set higher to avoid constant suspend/resume cycles eating 60-sec minimums
Disable auto-suspendGenerally avoidOnly if heavy steady workload OR zero-latency startup required
Auto-resumeEnable if cost/access not a concernDisable for cost control or access restriction — resume manually instead
⚠ To disable auto-suspend: set Never in UI or 0 / NULL in SQL. Running 24/7 on a 2XL+ = very significant cost.

Multi-cluster warehouse configuration rules Enterprise+
If on Enterprise Edition → all warehouses should be MCW.
Default to Auto-scale mode unless you specifically need Maximized.
Min = 1 (default) — extra clusters only start when needed. Set higher if HA is critical (protects against cluster failure).
Max = as large as practical — but watch credits. Example: XL × 10 clusters = 160 credits/hr if all run.
SHOW TABLES / DDL metadata commands do NOT require a warehouse → no credits charged.
