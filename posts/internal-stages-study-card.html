Exam traps
Trap 1 — user stage = 1 user, 1 table
False. User stage = 1 user, MANY tables. Table stage = many users, 1 table. Easy to flip.
Trap 2 — table stage can be dropped
False. Table and user stages cannot be altered or dropped. Only named stages can.
Trap 3 — table stage supports Iceberg tables
False. Iceberg tables don't support table stages.
Trap 4 — table stage supports transform on load
False. Table stages do not support using a query as COPY INTO source (no transformation). Named and user stages do.
Trap 5 — encryption can be changed after creation
False. For named stages, encryption type cannot be changed after the stage is created.
Named stage SQL: CREATE STAGE my_stage ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE');
Change key: ALTER TABLE t CLUSTER BY (col) — N/A for stages, but ALTER STAGE works for named stages.
Recommended for: any production pipeline with multiple users or tables → always use Named.
Practice questions
Score:0 / 0
1. Multiple users need to load files into a single table. Which stage type is most appropriate?
Table stage is designed for: many users → one table. User stage is for: one user → many tables. Named stage is most flexible but the question specifically describes the table stage use case.
2. A developer wants to load data from a stage and apply a SQL transformation during the COPY INTO. Which stage type does NOT support this?
Table stages do NOT support transforming data while loading — you cannot use a query as the source in COPY INTO from a table stage. User and named stages both support transformation on load.
3. How do you reference a user stage in a PUT or LIST command?
User stage = @~ | Table stage = @%tablename | Named stage = @stagename. These prefixes are directly tested.
4. Which stage type is the ONLY one that supports granting privileges to roles?
Only named stages are proper database objects with grantable privileges. User stages are personal. Table stages are tied to the table and have no separate privileges — access is controlled by table OWNERSHIP.
5. An Iceberg table needs a stage for data loading. Which stage type should you avoid?
Iceberg tables in Snowflake do NOT support table stages. Use a named or user stage instead.
