Composite master key = Snowflake-managed key + Customer-managed key (CMK)
CMK lives in cloud KMS: AWS KMS, Azure Key Vault, GCP Cloud KMS
If CMK is revoked → Snowflake cannot decrypt your data. After 10 min unavailability, all ops stop.
CMK rotation: new CMK version picked up next time Snowflake rotates its internal AMK (~30 days). Old versions must NOT be deleted.
Benefit: you can kill Snowflake's data access instantly by revoking your CMK.
⚠ Deleting a rotated CMK version = permanent data loss. Snowflake cannot recover it.
End-to-end encryption flow
Internal stage: auto-encrypted by Snowflake client before upload + after load.
External stage: client-side encryption optional (recommended). If not encrypted → Snowflake encrypts on ingest.
Client-side encryption uses a 128-bit or 256-bit AES master key stored as Base64 in the MASTER_KEY stage param.
Protocol: random file key encrypts file → master key encrypts the random key → both uploaded together.
