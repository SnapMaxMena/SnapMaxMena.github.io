Snowflake Fail-safe Study Card for SnowPro Core

Continuous data protection lifecycle
Phase 1 Active data Normal operations. Data is live and queryable. No fixed duration
Phase 2 Time Travel User-controlled. Self-service recovery. Query historical data. 0–90 days (configurable)
Phase 3 — Fail-safe Fail-safe Snowflake-only recovery. Last resort. Starts when Time Travel ends. 7 days — non-configurable
Phase 4 Purged Data permanently deleted. No recovery possible. Gone forever
Key facts

Duration & configurability

  • Always 7 days
  • Non-configurable — you cannot change it
  • Starts immediately after Time Travel ends
  • A long-running Time Travel query delays data entering Fail-safe

Who can recover data?

  • Only Snowflake — not the customer
  • Used only for extreme operational failures
  • Best-effort basis — not guaranteed
  • Recovery can take hours to days

What it covers

  • Tables, schemas, databases
  • Permanent tables only
  • Transient & temporary tables: 0 days — no Fail-safe

Billing & storage

  • Fail-safe data counts toward storage costs
  • Recovery uses serverless compute (billed)
  • View usage via ACCOUNTADMIN in Snowsight → Admin → Cost Management

Limitation — Snowpipe Streaming Classic

Fail-safe does not support tables with data ingested by Snowpipe Streaming Classic. Recovery operations on those tables will fail completely.

Exam traps
Trap 1 — configurable?

Fail-safe is always 7 days. You cannot set it to 0, 3, or 14. Time Travel is configurable (0–90 days). Fail-safe is not.

Trap 2 — who controls recovery?

You cannot query or restore from Fail-safe yourself. Only Snowflake support can. It is not a self-service feature like Time Travel.

Trap 3 — transient & temporary tables

Transient and temporary tables have no Fail-safe period (0 days). This is often why they're cheaper — less storage overhead. Permanent tables = 7 days Fail-safe.

Trap 4 — purpose

Fail-safe is not for accessing historical data after Time Travel expires. It exists only for Snowflake to recover from catastrophic system failures or security breaches.

Practice questions
Score:0 / 0
1. How long is the Fail-safe retention period, and can it be configured?
Fail-safe is always exactly 7 days and cannot be changed by users. DATA_RETENTION_TIME_IN_DAYS controls Time Travel, not Fail-safe.
2. A user's Time Travel period has expired. They contact Snowflake support to recover deleted data. What is TRUE?
Fail-safe is managed exclusively by Snowflake, on a best-effort basis. Users cannot access or query it. Recovery is not guaranteed and takes hours to days.
3. Which table type has ZERO days of Fail-safe protection?
Transient and temporary tables have 0 days of Fail-safe (and max 1 day Time Travel). This reduces storage costs — a common reason to choose transient tables for staging/ETL data.
4. When does the Fail-safe period begin?
Fail-safe starts right when Time Travel ends. If Time Travel is 1 day, Fail-safe starts on day 2. If Time Travel is 90 days, Fail-safe starts on day 91. Note: a long-running Time Travel query can delay data entering Fail-safe.
