MethodSyntaxUse when
TIMESTAMPAT(TIMESTAMP => '...'::timestamp_tz)You know the exact date/time
OFFSETAT(OFFSET => -60*5) (seconds from now)Relative time (e.g. "5 min ago")
STATEMENTBEFORE(STATEMENT => 'query_id')Undo a specific query by ID
AT = at or after that point. BEFORE = immediately before that statement's changes.

✗ External tables
Not clonable via Time Travel
✗ Internal (Snowflake) stages
Not clonable
✗ User tasks (with timestamp)
CREATE SCHEMA … CLONE s1 AT(TIMESTAMP=>...) does NOT clone tasks
⚠ Hybrid tables in schemas
Can clone for databases but NOT for schemas
Changing retention — effects on existing data
Data already in Time Travel is retained for the longer new period.
Data already in Fail-safe is not brought back — increase only helps future/current TT data.
Example: 10-day → 20-day. Data that would've left after day 10 stays 10 more days.
Data still within the new shorter period → stays in Time Travel.
Data outside the new period → moves to Fail-safe (background process — not immediate).
Applies to active objects only. Already-dropped child objects retain their period at drop time.
Example: 10-day → 1-day. Days 2–10 move to Fail-safe. Only day 1 remains in TT.
Dropping a DB: child schemas/tables use the DB's retention, ignoring their own explicit settings.
Dropping a Schema: child tables use the schema's retention, ignoring their own.
Fix: drop child objects explicitly first to honor their individual retention periods.
⚠ Exam trap: child table has 90-day retention but parent schema has 1-day → drop schema → table gets 1 day, NOT 90.
UNDROP rules & access control
What can be UNDROPped
TABLE · SCHEMA · DATABASE · NOTEBOOK · ICEBERG TABLE · DYNAMIC TABLE · EXTERNAL VOLUME · TAG · ACCOUNT
Privileges required
OWNERSHIP on dropped object
+ CREATE privilege on the object type in the target DB/Schema
If same name exists → UNDROP fails. Rename existing object first, then UNDROP.
UNDROP restores to most recent dropped version. Creating a new object with same name does NOT restore old one.
List dropped objects: SHOW TABLES HISTORY / SHOW SCHEMAS HISTORY / SHOW DATABASES HISTORY
Restoring only works in the current DB/Schema context, even with fully-qualified names.
