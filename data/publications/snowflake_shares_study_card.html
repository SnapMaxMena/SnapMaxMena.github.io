Snowflake Secure Data Sharing — Shares study card for SnowPro Core

The one thing to never forget
No data is copied or transferred. Sharing works through Snowflake's services layer and metadata store. The consumer queries the provider's data in place — zero storage cost to the consumer, compute cost only.
Rules every exam question tests

Provider rules

  • Can create unlimited shares
  • Can add unlimited accounts to a share
  • Can share from multiple DBs — but must be same account
  • New/updated objects available immediately
  • Can revoke access at any time
  • Must use ACCOUNTADMIN role

Consumer rules

  • Can consume unlimited shares
  • One database per share — hard limit
  • Shared objects are read-only — no DML
  • No storage cost — data lives in provider's account
  • Pays only for compute (virtual warehouse)
  • Access controlled via standard RBAC

Shareable objects

Tables · Dynamic tables · External tables · Iceberg tables · Regular views · Secure views · Secure materialized views · Semantic views · UDFs · Cortex Search services

Key point Secure views are preferred over regular views when sharing — they hide the underlying query definition from consumers.

4 sharing methods

1 Direct Share

Share specific DB objects directly to another account in the same region.

2 Listing

Share + metadata offered as a data product. Can be private or on the Snowflake Marketplace.

3 Data Exchange

Managed group of accounts — share within that group.

4 Clean Room

Share data AND control which queries the consumer can run against it.

Reader accounts (exam favourite)
Purpose: Share data with a consumer who has no Snowflake account. Provider creates and owns the reader account. Reader account can only consume from its one provider — not from others. Users in reader accounts can query only — no DML (no INSERT, UPDATE, DELETE, data loading).
Exam traps
Trap 1 — data is copied
False. Zero data is copied. Sharing is metadata-only. Consumer storage cost = $0.
Trap 2 — consumer can create multiple DBs from one share
False. Exactly one database per share per consumer account.
Trap 3 — cross-region direct share works natively
False. Direct Share requires accounts to be in the same region. Cross-region requires replication or listings.
Trap 4 — consumer pays storage
False. Consumer pays only for compute. Storage stays in and is billed to the provider.
Trap 5 — reader account can access other providers
False. Reader accounts are locked to the single provider that created them.
Practice questions
Score:0 / 0
1. A data consumer creates a database from a share. What is TRUE about storage costs?
No data is copied. Sharing uses Snowflake's services layer and metadata. The consumer's only charge is for compute (virtual warehouse) used to query the imported data.
2. How many databases can a consumer create from a single share?
Hard rule: one database per share per consumer account. However, a consumer can consume unlimited shares and create one DB from each.
3. A provider wants to share data with a partner who has no Snowflake account. What is the correct approach?
Reader accounts let providers share data with non-Snowflake consumers. The provider creates and owns the reader account. Users in it can only query — no DML allowed. The reader account can only consume data from its one provider.
4. A provider shares a table via a SHARE object and adds new rows to it. When do consumers see the new data?
Because no data is copied, updates to existing objects in a share are immediately visible to consumers. There is no sync lag — the consumer queries the live provider data directly.
5. Which role is required to create and manage shares?
Creating and managing shares requires the ACCOUNTADMIN role — the highest level role in a Snowflake account hierarchy.
